# The kernel chain DUI_DOT1X rewritten in one transaction (docs/drivers/sonic.md
# 11.26.12), 2026-11-15, image igmp-202511.20261115-6c8eb1cf7 (ebtables and
# iptables 1.8.11, nf_tables; kernel 6.12.41).
#
# semantics, netns, iptables: in private network namespaces on the switch
#   (ip netns; nothing the switch's own tables see), before the lock.
#   semantics: what ebtables-restore --noflush (nf_tables), iptables-restore -n
#   and ebtables-legacy-restore --noflush do with a declared chain, a jump
#   insert, a refused line and a removal. netns: a bridge with one veth port;
#   02:00:00:00:0c:01 (never admitted) sends untagged 0x88B5 broadcast frames
#   every 0.2 ms; a hand chain DUI_T (as l2d writes DUI_DOT1X: two EAPOL
#   ACCEPTs, admitted RETURNs, the port's DROP) is rewritten 200 times with
#   the admissions alternating, "old" by a flush and one ebtables call per
#   rule (the deployed l2d's way, each call run through ip netns exec),
#   "new" by one ebtables-restore --noflush; a CONTINUE rule after the jump
#   counts what passed. iptables: acl_cpu.go's mirror (DUI_ACL_CPU and two
#   table chains) rewritten 200 times by iptables-restore -n while a blocked
#   source sends UDP every 0.2 ms; an ACCEPT after the hook counts what passed.
# The rest under the test lock (22:14:46-22:28:32 UTC): empty cage 30
#   (Ethernet116, ce29) in MAC loopback, STP-blocked (Backup) in Vlan4094;
#   the test deb (a2306c0) installed, its bridge left to install l2d, then
#   stopped; l2.json's dot1x section by hand (Ethernet116 mac_based, idle
#   timeout 10 s, RADIUS 127.0.0.1:18120, hostapd's integrated server with
#   MACACL users 020000000A01 and 020000000A03); CONFIG_DB PORT|Ethernet116
#   learn_mode drop by hand. Afterwards the deployed deb (fef74fe)
#   reinstalled from /host/disunified and every hand change undone.
#   probe: which frames from an unadmitted source sent into the loop reach
#   ebtables INPUT (a CONTINUE rule ahead of the jump) and the netdev
#   (tcpdump -Q in): pae = untagged 0x88B5 to 01:80:c2:00:00:03, arppae = an
#   ARP request to that address, arp = a broadcast ARP request.
#   new_run / old_run: the same scenario through l2d, "new" the test deb's
#   (90dd8715...), "old" the deployed fef74fe l2d copied in (da9a6e83...):
#   02:00:00:00:0a:01 sends an ARP request every second, 02:00:00:00:0a:03
#   for 15 s of every 35 (revoked after 10 s idle, admitted again), l2d
#   restarted at 60 s and 136 s, the loop off for 4 s at 100 s;
#   02:00:00:00:0c:01 (no user) every second. Each run's sections:
#     <run>_start   ebtables -L as the run started
#     <run>_events  xtables-monitor -e for the run: each rule event of the
#                   bridge filter table, and NEWGEN after each nf_tables
#                   transaction (its generation, pid and program); only
#                   ebtables events were printed
#     <run>_chain   ebtables -L DUI_DOT1X polled every ~5 ms: a line on each
#                   change (epoch seconds, rule count, the rules)
#   run: the rig's own log (setup, probe, the two runs' counters, restore).
# Nothing scrubbed: test addresses only (02:00:00:00:xx:xx, 192.0.2.0/24,
# 127.0.0.1); the LAN's multicast sources that the loop brings back are in
# l2d's journal only, which is not kept.
